# What is in this repository, and what is deliberately not

Not legal advice. This is a description of what was actually done and why,
written so that anyone can check it rather than take it on trust.

## The rule

**The numbers travel. The game does not.**

Everything here is either a measurement, or something this project wrote. There
is no game code, no artwork, no audio, no ROM, no patch, and no link to any of
those. That is not a promise to be taken on faith — it is enforced by
`tools/validate.py`, which runs on every pull request, and it is a *whitelist*:
any string in any data file that does not match a pattern this project
generates fails the build.

`tools/prove_validator.py` injects eight kinds of leak — a source symbol, an
artwork name, a lane label, a borrowed sentence, and four structural faults —
and demonstrates that each is rejected. A check that has only ever passed is
not a check.

## Never in this repository

| | why |
|---|---|
| game source, in any form or any language | not ours |
| artwork, sprites, sprite rips, screenshots | not ours |
| audio, in any form | not ours |
| ROMs, ROM fragments, patches, diffs against a ROM | not ours |
| names of routines, labels, files or artwork from the game | short and functional, but still lifted, and the whitelist blocks them |
| links to anywhere hosting any of the above | pointing at it is its own problem |

### The one exception, stated rather than hidden

`tools/validate.py` carries a short list of terms it refuses to let through,
and a blacklist has to name what it blocks. So roughly a dozen real terms do
exist in this repository - in the file whose entire job is keeping them out of
every other file.

They are split across adjacent string literals there, which the language
rejoins at runtime, so the check works while no line reads as the term. That
is a defence against a careless copy-paste, not a claim that they are absent.
They are not absent. Eleven functional words in one validator is the price of
having a validator, and a project that quietly pretended otherwise would be
worth less than one that says so.

Everywhere else - including the fixtures in `tools/prove_validator.py`, which
inject leaks on purpose - the names are invented. Those checks match on shape,
so a real name would prove nothing a made-up one does not while leaving the
real one in a public repository.

## What the data actually is

Rectangles and integers.

A strike record is a box and two damage bytes. A pose is a list of rectangles
describing where the pieces of a sprite sit relative to its anchor — the
*extents*, not the pixels. Frame data is counts of ticks. None of it can be
used to reconstruct any part of the game, and all of it is the kind of factual
description a strategy guide has always contained.

Identifiers are generated by this project (`headband/hikick`), not taken from
anywhere. Where the game's own tables share one record between characters, that
is recorded as a membership list rather than by repeating a name.

## Character names

There are none. The seventeen fighters carry handles this project chose -
Hathead, Sword Arms, Knockout, Bombshell, Big Arms, Four Arms, Final Boss and
the rest - each one a plain description of how you tell that fighter apart on
screen. No trademarked character name appears in any data file, in the viewer,
or in these documents.

That is a stronger position than nominative use, which would also have been
available: a viewer calling them Fighter 1 through Fighter 17 would be useless,
but a viewer calling them by what they visibly are is not. `Sword Arms` tells
you who is on screen as well as the trademark does.

Five of the seventeen - Hathead, Sword Arms, Knockout, Bombshell and Final
Boss - are how the game's own developers described those fighters in passing.
That is worth stating plainly rather than dressing up as coincidence. It is
also the limit of it: a two-word description of what a fighter looks like is
not the game's code, its artwork, or its structure, and it discloses nothing
that watching the attract mode would not. The twelve others were coined here.

What stays out is what always stayed out. No routine name, label, filename or
symbol appears in this repository under any handle, and `tools/validate.py`
blocks that class of string in prose and in data exactly as it did before.

## If you think something here crosses a line

Open an issue, or contact the maintainers, and say which file and which line.
Anything genuinely over the line comes out — that is a cheaper conversation for
everyone than the alternative, and this project would rather be corrected than
be right.
